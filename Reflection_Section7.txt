1. What happens, step by step, when someone types your website address into their phone (client, server, DNS, HTTPS)?
When a visitor types my GitHub Pages URL into their phone browser, the phone acts as the client and sends a request to a DNS (Domain Name System) resolver to translate the human-readable domain name into the numerical IP address of GitHub's hosting server. Once the IP address is returned, the phone initiates a TCP connection and performs a TLS handshake to establish an encrypted HTTPS session so data cannot be intercepted or tampered with in transit. The browser then sends an HTTP GET request over that secure tunnel asking the server for index.html. GitHub's server locates the stored HTML, CSS, and image files and streams them back to the phone, which parses the code and renders the portfolio on screen.

2. What is the difference between your static website and a dynamic one? Give one example from your own portfolio.
A static website delivers pre-built HTML, CSS, and media files directly to every visitor exactly as they are stored on the server, without executing server-side code or querying a live database on each page load. In contrast, a dynamic website generates or updates content on the fly using server-side scripts and a database based on user actions, logins, or live data. In my own portfolio, cinema.html and hobbies.html are static because my Top 5 horror movies (Insidious, The Conjuring, The Pope's Exorcist, The Devil Made Me Do It, and The Bride) and rap tracks are hard-coded into the HTML. If I connected my contact.html form or movie rankings directly to portfolio.db via a backend API so visitors could submit live messages or vote on rankings in real time, that feature would become dynamic.

3. Why do we use a separate CSS file instead of styling each page individually?
Using a single external stylesheet (style.css) linked across all five HTML pages enforces the DRY (Don't Repeat Yourself) principle and guarantees visual consistency in colors, typography, and navigation layout. If I want to update my obsidian-and-champagne-gold color palette or adjust card spacing across the entire site, I only edit one CSS file instead of modifying five separate HTML documents. External CSS also improves performance because the visitor's browser caches style.css after loading the Home page, making subsequent navigation to academic.html, hobbies.html, cinema.html, and contact.html faster. Finally, separating structure (HTML) from presentation (CSS) keeps the codebase clean, readable, and easy to debug.

4. Which accessibility or responsive design choices did you make, and why do they matter?
For responsive design, I included the viewport meta tag and built layouts using CSS Grid (repeat(auto-fit, minmax(...))) and a @media (max-width: 768px) breakpoint so multi-column grids collapse cleanly into a single column on smartphones. I also used clamp() for fluid heading sizes and constrained images with width: 100% and object-fit: cover so photos never overflow narrow screens. For accessibility, I used semantic HTML5 landmarks (<header>, <nav>, <main>, <article>, <footer>), paired every form input with an explicit <label>, maintained high contrast between light slate text (#E2E8F0) and the dark obsidian background (#070B12), and wrote descriptive alt text for every image so screen-reader users can understand the visual content.

5. In your database, which field is a primary key and which is a foreign key? Why are they needed?
In portfolio.db, project_id in the projects table, activity_id in the activities table, and message_id in the messages table serve as primary keys (PRIMARY KEY AUTOINCREMENT). In the messages table, project_id and activity_id act as foreign keys (FOREIGN KEY) referencing the primary keys of projects and activities respectively. Primary keys are essential because they guarantee every record has a unique, non-null identifier so individual rows can be retrieved, updated, or deleted without ambiguity. Foreign keys enforce referential integrity between tables, preventing orphan references and enabling JOIN queries that link visitor messages to the exact academic project or hobby they inquired about.
